# MiniCPM-V 4.7-1B 编译与 CUDA Graph 对照实测

2026-10-16，RTX5060Ti16GB、WSL Ubuntu26.04独立Docker、vLLM0.32.0rc1.dev277+g642c18d64。

**已找到主要瓶颈：旧启动脚本强制 enforce_eager，关闭了默认编译和CUDA Graph。取消该设置后，固定输出的解码由约57提升至231–236 tokens/秒，约4.1倍。**

这是“eager”与“默认Torch编译＋CUDA Graph”的组合对比，不能把所有收益单独归因于CUDA Graph；没有做compile-only/graph-only消融。

每种输入先预热1次，再测4次；每次强制输出256tokens，temperature0、min_tokens=max_tokens256、ignore_eos=true，排除了回答长度差异。两种服务共40次请求（32次纳入统计），全部成功。强制输出只是速度诊断，不用于评价答案质量。

纯文本与五图的解码速度都接近57→234，说明旧版慢速主要位于逐token执行路径，而非图片编码本身。五图原图输入的首字仍约0.86–0.89秒；视觉前处理/编码与输入传输的成本未随解码同比下降。多模态缓存可命中或被驱逐，首字时间只反映本次请求顺序，不是纯视觉编码器的独立计时。

项目完整流程也使用同一段8秒视频、同样1次联系图＋2次细节调用：**14.34→7.15秒，约2.01倍**。模型调用合计12.04→4.86秒，复制/抽帧等开销约2.3秒。优化后流程3次调用均完成。单个视频单次端到端对比，不代表全体视频吞吐。

优化不会修复1B模型的动作、方向、景别或时间码错误。保留原图5帧分析作为原流程；960短描述仍适合快速预览。没有为提升速度而缩短本次原流程的输出上限或提示词。

## 已落地的配置

- 模型注册表为4.7设置 `vllm_args.enforce_eager=false`；其他模型保留原先默认。
- 启动脚本按模型配置选择eager；`MINICPM_ENFORCE_EAGER=1`可回退。比较现有容器的实际启动参数与缓存挂载，性能参数变化时重建，避免同模型/镜像静默复用旧参数。
- 编译、FlashInfer缓存挂载到 `~/.cache/minicpm-v47`。本机此路径指向本次缓存目录 `~/.cache/minicpm-v47-graph-20261016`，重建容器后仍能保留。可用 `MINICPM_RUNTIME_CACHE_DIR`覆盖。
- 当前 `vision-minicpm` 已运行更快配置，API仍为8002，WebUI仍为7877。旧 eager 容器停止保留为 `vision-minicpm-eager-20261016`。
- 本次首次优化启动总耗时142.16秒，其中日志记录Torch编译12.59秒、图捕获约1秒；其余含模型加载、内核预热、图显存探测等。启动耗时未纳入推理结果；尚未测带缓存重启的耗时。
- 优化后五图实测GPU占用峰值14118MiB（13.79GiB），eager基线13980MiB；包括预留/KV缓存，未测试与ComfyUI同时渲染。
- 模型权重、版本、上下文16384、显存预算0.8、max_num_seqs1、image5/video0、关闭thinking、关闭prefix caching等均相同。
