# Agent 任务文件存放标准 v1

## 项目目录

用户提供素材文件夹时，默认在其中创建 `agent_work`；不移动、不重命名、不覆盖用户原始素材。
没有指定项目目录时，使用部署输出根目录下 `agent-projects/<日期>_<任务名>`，不使用桌面根目录、仓库根目录或系统临时目录散放业务文件。

初始化：`bash scripts/yegou workspace init --root /path/to/project/agent_work`。
提交：`bash scripts/yegou dub --workspace /path/to/project/agent_work --input /path/to/video.mp4 --voice voice_id`。
HTTP 请求同样支持 `workspace` 字段。指定 workspace 时默认输出到 `04_outputs`；显式 output 优先。

| 目录 | 内容 | 保留规则 |
|---|---|---|
| `01_config` | 原始素材路径清单、请求 JSON、角色音色映射、人工校正时间轴 | 长期保留 |
| `02_work/<job_id>` | 提取音轨、分离轨、逐句配音等可重建中间文件 | 交付验收后保留 7 天再按需清理 |
| `03_voices` | 角色参考 WAV、精确台词、起止时间和质量说明 | 与项目长期保留 |
| `04_outputs` | 成片、字幕、最终音轨和质量报告 | 长期保留，不作为缓存删除 |
| `05_logs/<job_id>` | 状态快照、追加事件记录和验证信息 | 长期保留 |
| `99_tmp/<job_id>` | 下载片段、探测输出、临时转码、临时脚本 | 成功且确认结果存在后删除；失败保留 7 天供排错 |

`workspace.json` 记录版本、目录用途和素材清单。目录名稳定，任务 ID 不复用；不同任务不得共写同一临时文件。
临时文件命名使用 `<用途>_<短ID>.<扩展名>`，未完成的写入使用 `.part` 或 `.tmp`，成功后原子替换。

## 原始素材与音色

原始视频和剧本只读使用，在配置中记录绝对路径、文件大小和 SHA256；需要截取时写入任务目录。
参考音色必须记录角色名称、原片时间范围、参考文字、处理参数；项目音色放 `03_voices`，复用音色库保留不可变的注册副本。
不要将 token、口令写入配置、日志或项目清单。

## 服务内部状态的边界

项目目录存放 agent 自己产生的业务文件。现有 7866 引擎仍把上传副本、内部清单和部分工作缓存存放在 `VOICE_STATE_DIR`；7868 控制服务的队列、音色库和权威任务状态存放在 `YEGOU_AGENT_STATE`。
这些是服务内部状态，不应在运行中移动或删除。`--workspace` 会把请求配置、状态快照、事件日志及最终输出放进项目，但不会迁移旧引擎的所有内部缓存。
因此不能声称启用 workspace 后所有 Docker 中间文件都会自动转移。agent 后续新增的截帧、试听、字幕编辑和临时脚本必须遵守项目目录规则。

## 清理

不默认自动删除用户素材、成片、项目音色或复现记录。
清理仅针对已终止任务的 `99_tmp/<job_id>` 和已验收且超过保留期的 `02_work/<job_id>`。
删除前核对路径确实位于对应项目目录内、任务未运行、交付文件存在，并保留清理记录。失败/待复核任务不在运行期间自动清理。
模型权重、公共缓存、Docker 镜像和服务状态不参与项目级临时文件清理。
